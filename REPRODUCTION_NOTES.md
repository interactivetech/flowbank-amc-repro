# Fidelity and deviations

Sources: [paper, Appendix D.1](https://arxiv.org/abs/2606.11290), [official code](https://github.com/umd-huang-lab/FlowBank), pinned at `dde948d9f65cede15e6a3418dde3bf7feffdd087`. Original clone is in `vendor/FlowBank`; PDF and extracted text are in `sources/`. Prompts are transcribed from PDF because arXiv HTML drops code blocks. PDF line wrapping and indentation are normalized; wording and the literal doubled braces in W4 are preserved. No generic round_1 graph is used.

| Condition | Appendix D.1 graph | Reproduction |
|---|---|---|
| W1 | general, analytical, verbose Custom → ScEnsemble | Three sequential independent calls, then original LLM selector; selected candidate text returned |
| W2 | three analytical Custom → ScEnsemble → Programmer | W2-specific analytical prompt, including avoid-assumptions sentence; returns code plus execution output |
| W3 | logical, thorough, concise Custom → ScEnsemble → Programmer | Distinct published prompts, same execution order and final return |
| W4 | classifier Custom → specialist Custom | Geometry/combinatorics/number substring routing; algebra default, including malformed classification |
| baseline | additional experimental control | One call using W1 general solve prompt; no other operators |

Custom performs the released placeholder substitution or direct instruction+problem concatenation, even when no separating newline is present. ScEnsemble copies the released SC_ENSEMBLE_PROMPT and XML formatter suffix verbatim, labels candidates A/B/C, parses solution_letter, and returns that candidate. It is **an additional LLM call**, never a Python majority vote. Invalid selections become execution failures, not arbitrary candidate defaults.

Programmer copies PYTHON_CODE_VERIFIER_PROMPT and CodeFormatter instructions. It attempts at most three generations, with execution-error feedback, and stops after successful execution regardless of mathematical correctness. It returns `Code:\n...\nOutput: ...` exactly as released; there is no post-verification solve call. Unlike the upstream tree-sitter sanitizer, this version extracts fenced or raw Python and validates syntax plus the solve function without deleting unrelated code. This deviation is explicit and can change code acceptance. Syntax failures receive execution-error feedback. The upstream outer exception retry decorator is replaced by bounded infrastructure retries in the client and resume checkpoints. No answer-dependent retries occur.

The upstream host process-pool exec and import denylist are replaced by Docker isolation: no network/mounts, read-only root, nonroot UID, all capabilities dropped, no-new-privileges, PID/memory/CPU/file limits, 16 MiB temporary storage, 20-second wall timeout, bounded captured output. SymPy, NumPy, SciPy are available in the sandbox. The image ID is recorded. A missing daemon/image fails preflight before workflow calls. No unrestricted generated code executes on the host.

Published executor: GPT-4o-mini, temperature 0. The initial experiment attempted the endpoint-discovered Qwen, temperature 0, top-p 1, seed 42, max_tokens 4096, enable_thinking false. The final executed model was changed by the user to DeepSeek Flash on port 8000; see the executor-change section below. Output cap and thinking behavior match released async_llm.py; they are configurable. The server reports max_model_len=204800, which is context capacity, not evidence for 128K generated output. API acceptance of a seed or thinking parameter does not prove server enforcement. Actual parameters, response usage, response model, finish reason, and raw responses are retained. At temperature 0, repeated W2 calls can be identical; we preserve this rather than introduce unreported sampling diversity.

## Grading

All 655 rows contain problem, solution, type, level; no native ID. IDs encode the zero-based row index and manifest includes one-based line number plus the complete original row. Dataset SHA256 and seed bind selection before model calls. The 3-question smoke subset is the first three members of the 50-question subset under Python Random(42). Original solutions are retained; their leading `Answer: $(D) expression$` format or final boxed expression supplies reference answers. All 655 references pass parse preflight.

FlowBank's AMC grader extracts the last box or last sentence; compares floats with absolute tolerance 1e-3; tries SymPy; uses LLM extraction, then an LLM judge which can override a rule-based failure. We intentionally use deterministic extraction and math-verify 0.9.0 without either LLM stage. Balanced-brace extraction handles nested LaTeX. For Programmer returns, only the execution output is graded, avoiding boxes in code/comments. Plain final expressions and explicit answer lines are supported. Unparseable predictions are separate from math errors. Malformed boxes fail parsing rather than rescuing unrelated numbers. Gold parse failures abort before generation. These choices differ from FlowBank and may materially change scores.

Ground truth never enters the graph/client. Candidate correctness is attached retrospectively after graph completion. Correct-candidate loss is attributed to aggregation if the selector chose an incorrect candidate, verification if it chose a correct candidate but Programmer lost it, or selection parsing failure; these are descriptive stage attributions, not claims of communication failure.

## Reliability and interpretation

Default concurrency is 1, rate limit 30 requests/minute, request timeout 180s. Connection/timeouts/429/5xx get up to three retries with exponential backoff. 401/403 and other nonretryable 4xx fail immediately. Final answer and selector parse failures are not automatically retried. Resume reuses successful stage calls even within an unfinished workflow. Failed infrastructure stages can be retried by resume; completed evaluations (including mathematically wrong/unparseable outputs) never rerun. A crash between response receipt and checkpoint fsync can still repeat that call; the remote API offers no transactional exactly-once guarantee. Run only one runner per result directory.

Offline analysis refuses incomplete matrices instead of treating missing results as wrong. Token counts use reported usage; retries with unknown server-side usage cannot be billed exactly. Client metadata and source hashes are immutable for resume. Oracle counts at least one correct W1–W4 answer, excludes baseline, and is retrospective ground-truth upper-bound coverage. Oracle costs sum all four workflow costs; it is never GNN selector accuracy. Unique wins are relative to the four workflows. Small-subset gains are descriptive; they do not establish population-level significance. No W5, optimizer, GNN, or DeepMath work is included.

## User-authorized executor change (2026-11-02)

The Qwen endpoint on port 8001 was busy: its first two AMC requests each timed out on three consecutive 180-second attempts. The user redirected this task to port 8000, then explicitly selected `deepseek-v4-flash` after model discovery revealed that Qwen was unavailable there. The interrupted Qwen traces and original code snapshot are preserved in `results/smoke_8001_interrupted/` and `sources/attempt_8001_code/`; no Qwen accuracy is claimed and those attempts are excluded from DeepSeek results.

The new endpoint advertises `deepseek-v4-flash`, owned_by `ds4.c`, with display name `DeepSeek V4.1 Flash`. This is the server-advertised identity, not independent verification of model weights or engine implementation. Both advertised aliases have that display name; only the selected Flash alias is used. We do not describe this endpoint as verified vLLM. The model is a deliberate departure from the original Qwen experiment, authorized before any AMC inference on port 8000.

The client uses `extra_body={"thinking":{"type":"disabled"}}` for DeepSeek, following the [official thinking-mode API](https://api-docs.deepseek.com/guides/thinking_mode/), and retains the original Qwen chat_template_kwargs path for Qwen. The local service accepts this parameter; enforcement cannot be established solely by API acceptance. Minimal completion returned OK, with no reasoning field. Other inference settings remain temperature 0, top-p 1, seed 42, max_tokens 4096. Actual request settings and raw responses are saved. No context-length advertisement is treated as permission to generate million-token answers.

Usage completeness now requires usage on every attempt, including failed requests. If retries consume unreported server tokens, table token means are unavailable rather than assumed complete. The sandbox executes the immutable preflight image ID, not a mutable tag. The initial sandbox tag disappeared externally during the endpoint switch and was rebuilt from the pinned Dockerfile; isolation tests were rerun.
